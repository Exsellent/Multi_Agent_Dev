== 1. Project Overview

The system implements a multi-agent architecture in which:

* each agent is a separate service;
* interaction is carried out via the MCP protocol;
* orchestration is performed using n8n;
* scalability and fault tolerance are supported;
* LLM is used for analysis, generation, and reasoning;
* a multimodal agent is present (working with images).

== 3. Agents

=== 3.1 Planner Agent

**Purpose:**
- strategic task decomposition;
- predictive estimation;
- risk-aware planning.

=== 3.2 Risks Agent

**Purpose:**
- deep security and compliance risk analysis;
- identification of vulnerabilities and threats.

=== 3.3 Architecture Intelligence Agent

**Purpose:**
- multimodal analysis of architecture diagrams;
- failure propagation simulation;
- refactoring recommendations.

=== 3.4 Code Execution Agent

**Purpose:**
- autonomous code generation;
- execution and testing;
- self-correction loops.

=== 3.5 Marathon Agent

**Purpose:**
- long-running tasks;
- persistent state and thought signatures.

=== 3.6 Metrics Agent

**Purpose:**
- collection and accounting of processing metrics;
- request counting;
- data preparation for monitoring.

=== 3.7 Health Monitor

**Purpose:**
- checking agent availability;
- health-check endpoints;
- foundation for system observability.

== 4. MCP Protocol for Interaction

All agents accept requests in the format:

[source,json]
----
{
  "method": "tools/<method_name>",
  "params": { ... }
}
----

And return a structured response:

[source,json]
----
{
  "result": "...",
  "reasoning": [
    {
      "step_number": 1,
      "description": "Step description",
      "input_data": {},
      "output_data": {}
    }
  ]
}
----

This format provides:
- transparency of operation;
- traceability of decisions;
- ease of debugging.

== 5. Deployment

=== 5.1 Requirements

* Docker
* Docker Compose
* Linux / WSL / macOS
* PlantUML plugin installed (for documentation)

=== 5.2 Starting the System

[source,bash]
----
docker compose up --build
----

After launch, the following become available:

* n8n — http://localhost:5678
* agents — ports 8201–8207
* health-check — `/health`

== 6. Environment Variables

All secrets are stored in `.env` and are not committed to the repository.

Example:

[source,env]
----
LLM_PROVIDER=groq
GROQ_API_KEY=xxxx

VISION_PROVIDER=openrouter
OPENROUTER_API_KEY=XXXXXXXXXXXXX
VISION_MODEL=

JIRA_URL=https://
JIRA_API_TOKEN=XXXXXXXXXXX
JIRA_PROJECT_KEY=PROJ

LOG_LEVEL=INFO
PYTHONUNBUFFERED=1
----

== 7. Observability and Resilience

* each agent has `/health`;
* errors are logged;
* failure of one agent does not stop the system;
* n8n can retry calls;
* metrics are collected via Metrics Agent.

---

== 8. Scalability

The architecture supports:

* adding new agents without changing the core;
* horizontal scaling of containers;
* replacing the LLM provider;
* extending MCP methods.
